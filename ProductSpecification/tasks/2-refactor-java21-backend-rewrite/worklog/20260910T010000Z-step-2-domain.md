## Divergences accepted

- `UuidText.parse` вместо `UUID.fromString`: повторяет питоновский `uuid.UUID(str)` (снятие `urn:`/`uuid:`,
  скобок и дефисов, ровно 32 hex). Строже Python на узком классе мусорного ввода, где `int(hex, 16)`
  терпит `+`, `_` и пробелы. Ни один acceptance-тест этот класс не покрывает; альтернатива
  (`UUID.fromString`) расходится с Python сильнее. Принято сознательно.
- `Pattern.UNICODE_CHARACTER_CLASS` в `Email` -- без него Java-классы символов не совпадают с питоновскими
  по умолчанию.
- `ChallengeStrategyRegistry` собирает карту явным циклом put, а не `Collectors.toMap`: словарное включение
  в Python берёт последнее значение при дубле ключа, `toMap` бросает.
- `User` -- плоский record с nullable-полями, а не `Optional`: зеркалит `X | None` в `user.py`.
  Решение обратимо ценой одного файла, если storage-полоса упрётся.

на `ttlSeconds`, усечение к нулю в `replayTtlSeconds`, `Normalizer.NFC` + `toLowerCase(Locale.ROOT)`

Родитель независимо перечитал `email.py` против `Email.java`, `user.py` против `User.java`,
`challenge_id.py` против `ChallengeId.java` и оба места вызова `UuidText`.

Единственная незеркалированная ветка: в Python `octet_length` заворачивает `UnicodeEncodeError`
в `ValidationException("Email is not valid text")`. В Java `getBytes(UTF_8)` не бросает, ветка недостижима.
