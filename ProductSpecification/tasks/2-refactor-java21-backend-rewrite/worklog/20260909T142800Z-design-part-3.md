**Решение пользователя: характеризационные тесты не пишутся.** Перенос опирается
только на существующий acceptance-набор; четыре OPEN-шва остаются непокрытыми и
принимаются как известный риск. Расхождение в них проявится в проде, а не в
сборке. Guard'ы, которые НЕ будут написаны, зафиксированы здесь как долг:

- S4: `test_should_swap_to_the_newer_challenge_exactly_once_under_concurrent_resend`
- S6: `test_should_refuse_safely_when_the_session_store_is_unavailable`
- S7: тест на зависший downstream-вызов с ограниченным временем отказа
- S8: поколоночная сверка Liquibase-changelog с текущей Alembic-схемой +

Компенсация без новых тестов: пункты S4/S7/S8 переходят в обязательные пункты
чек-листа шагов переноса (дословный Lua, `+00:00` в сериализации Redis-записи,
явные таймауты JDBC/Redis/Mail, построчная сверка changelog с Alembic).

## Блокер: четыре enabled acceptance-теста поднимают Python-подпроцессом

`acceptance/statements/signing_secret_boot_statements.py`
(`BOOT_PROBE = "from application.main import create_app; create_app()"`) и
`acceptance/statements/configuration_startup_statements.py`
(`ENTRYPOINT_PROBE = "import application.main"`) запускают `.venv/bin/python`.
После удаления Python-бэкенда четыре теста упадут с `ModuleNotFoundError`.

**Решение пользователя: JVM-пробник.** Заменить пробу на JVM-пробник — отдельный `main`-класс
`ConfigurationProbe` в `:backend:application`, который биндит
`@ConfigurationProperties`, не поднимает web/DB/Redis и выходит кодом ≠ 0 с
именем переменной в stderr. Меняются только Statements (harness), сами тесты —
нет; критерий приёмки «без правок самих тестов» соблюдён. Таймауты
`BOOT_TIMEOUT_SECONDS=60` и `STARTUP_TIMEOUT_SECONDS=25` поднимаются под старт JVM.

## Риски покраснения не из-за поведения

1. `/actuator/health` вместо `/health` — гарантированный красный `TestHealthAcceptance`.
2. Окно ожидания health в `test-acceptance.sh` — 30 с, холодный старт JVM может не уложиться.
3. `payload: null` в 401 исчезнет при глобальном `NON_NULL`; 10 nullable-полей профиля обязаны быть JSON `null`.
4. `write-dates-as-timestamps` по умолчанию даёт epoch-числа; наносекунды ломают `fromisoformat`.
5. Tomcat режет `Authorization` на 8192 октетах и отвечает HTML-400 вместо 401-конверта → `server.max-http-request-header-size: 16KB`.
6. `rename-command CONFIG ""` в `redis.conf` уронит приложение при любой фиче Spring, делающей `CONFIG SET`.
7. Формат даты в Redis-записи (`+00:00` против `Z`) тихо ломает `swap-challenge` в параллельной фазе.
8. `spring.datasource.hikari.maximum-pool-size` должен равняться `DB_POOL_SIZE` (дефолт 10) — иначе `connection_release` краснеет по времени.
