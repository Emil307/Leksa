## Известный шов: Content-Transfer-Encoding на не-ASCII теле

Полоса сняла сырые SMTP-байты с обеих сторон:

| | Python (aiosmtplib) | Java (Jakarta Mail) |
|---|---|---|
| ASCII-тело | `7bit`, `Hello` | `7bit`, `Hello` |
| кириллица | `8bit`, открытый текст | `base64` |
| Content-Type | `text/plain; charset="utf-8"` | `text/plain; charset=UTF-8` |
| Subject | RFC 2047 только на не-ASCII слова | RFC 2047 на всю строку |

Тема после декодирования идентична -- расхождение косметическое. CTE -- нет.
`acceptance/clients/mail/mailhog_client.py` ищет код регуляркой `(?<!\d)(\d{6})(?!\d)` в
`Content.Body` из MailHog; на кириллическом шаблоне `auth/email_code.html` base64 регуляркой не найдётся.

**Родитель проверил независимо, чем именно этот шов прикрыт сегодня.** Полоса написала, что
`get_email_sender()` не имеет потребителей -- это подтвердилось: `grep -rn get_email_sender backend/`
даёт единственное определение и ни одной ссылки, уведомления уходят в `OutboxNotificationQueue`,
диспетчера outbox не существует. Но существеннее другое: **enabled acceptance-тесты вообще не читают
MailHog.** `test_token_lifetime_acceptance.py` (без skip-маркера) берёт код через
`request_code_and_capture` -> `outbox_database.queued_code_for(...)`, то есть прямо из БД.
Путь `await_login_code` -> MailHog достижим только из `given_live_session`, а её вызывают
`test_token_refresh_acceptance.py` и `test_challenge_resend_acceptance.py` -- оба под `@pytest.mark.skip`.

Условие будущей поломки, дословно: разморозка истории 01 EmailCodeLogin вместе с появлением
диспетчера outbox и снятием skip-маркеров. Тогда извлечение кода из MailHog сломается на base64.
Это ровно тот класс открытых швов, который принят как известный риск («переносим как есть»),
и починка потребовала бы `mail.mime.allowutf8` плюс поддержки 8BITMIME сервером -- механизм
за пределами утверждённого дизайна. Не чиню, фиксирую.

## Прочие расхождения

- `MAIL_USE_TLS` -> `mail.smtp.ssl.enable`, а не `starttls.enable`: у aiosmtplib `use_tls=True`
  означает implicit TLS (для STARTTLS у него отдельный `start_tls`).
- **Новая переменная `MAIL_TIMEOUT_MILLIS`**, дефолт 60000 на `connectiontimeout`, `timeout`
  и `writetimeout`. В Python явного таймаута нет, работает дефолт `aiosmtplib.send(timeout=60)`,
  так что дефолт держит паритет. Добавление переменной в `infrastructure/.env` заведено
  отдельным чекбоксом в Step 10.
- Дефолты `localhost`/`1025` в `EmailProperties` -- дословная копия дефолтов `settings.py`.
  Убрать нельзя, не изменив поведение: Python стартует без `MAIL_PORT`. В рабочих средах
  `MAIL_PORT` из `.env` перекрывает их relaxed binding'ом.
- Тело без завершающего `\n`: Python `set_content("Hello")` даёт `"Hello\n"`, Jakarta Mail
  `setText("Hello")` -- `"Hello"`. Артефакт двух почтовых библиотек, тест ассертит фактическое.
- Java добавляет `Message-ID` и `Date` в `saveChanges()`; аддитивно.
