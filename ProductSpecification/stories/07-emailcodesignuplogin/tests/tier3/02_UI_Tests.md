## 1. Экран почты

### 1.2 Кнопка «Получить код» доступна только для адреса, похожего на адрес

Tier: 3 (hz-06) — локальная подсветка кнопки — удобство; без неё адрес уходит на сервер и отклоняется там с подсказкой, вход не блокируется; тяжесть последствия не установлена.

```gherkin
Дано пользователь на экране почты
Когда он вводит <адрес>
Тогда кнопка «Получить код» <состояние>
И запрос кода не отправляется
```

| адрес | состояние |
|---|---|
| пустая строка | недоступна |
| `ivan` — без символа «собака» | недоступна |
| `ivan@` — без доменной части | недоступна |
| `   ` — одни пробелы | недоступна |
| `ivan@example.com` | доступна |
| строка из 50 000 символов без «собаки» | недоступна — решение принимается за доли секунды, экран не подвисает |

## 2. Запрос кода

### 2.3 Адрес, который сервис не принял, остаётся на экране почты с подсказкой

Tier: 3 (hz-02, hz-06, hz-07) — адрес, прошедший локальную проверку, но отклонённый сервисом, — редкий случай; без подсказки пользователь получает общее сообщение и повторяет попытку; не установлено «не редко».

```gherkin
Дано пользователь на экране почты ввёл адрес, который сервис не принимает
Когда он нажимает «Получить код»
Тогда он остаётся на экране почты
И у поля адреса видна подсказка «Проверьте адрес»
И введённый адрес сохранён в поле
И кнопка «Получить код» снова доступна
```

### 2.6 Ответ, который приложение не понимает, показывается как недоступность сервиса

Tier: 3 (hz-02, hz-04, hz-05, hz-07) — строки таблицы — нарушения контракта бэкенда, уже закрытого acceptance-сьютом истории 01; реалистичен только 500 с HTML от прокси, и его деградация — закрытая кнопка до перезагрузки; не установлено «не редко».

```gherkin
Дано пользователь находится <где> и сервис отвечает на его действие <ответ, которого приложение не ждёт>
Когда он выполняет действие
Тогда видно сообщение «Сервис временно недоступен, попробуйте позже» без подробностей
И экран не меняется, введённые адрес или цифры сохранены
И кнопка действия снова доступна
И на экране нет «NaN», отсчёт не показывает ложный «0:00», кнопка повтора не закрыта навсегда
И в консоли браузера нет необработанной ошибки
```

| где | ответ, которого приложение не ждёт |
|---|---|
| на экране почты, нажимает «Получить код» | 500 с HTML-страницей |
| на экране почты, нажимает «Получить код» | 429 с конвертом ошибки с неизвестным `code` |
| на экране почты, нажимает «Получить код» | 200 без `challengeId` или без `expiresAt` |
| на экране почты, нажимает «Получить код» | 409 без `payload` или с `retryAfterSeconds: "abc"` |
| на экране кода, нажимает «Подтвердить» | 502 с текстом вместо JSON |
| на экране кода, нажимает «Подтвердить» | 200 с пустым телом |
| на экране кода, нажимает «Подтвердить» | 200 без `session` |
| на экране кода, нажимает «Отправить новый код» | 200 с неразбираемым `expiresAt` |

### 2.7 Адрес с нелатинскими символами уходит и показывается как введён

Tier: 3 (hz-01, hz-05) — кириллические и IDN-адреса редки; обрезка пробелов по краям деградирует до подсказки «Проверьте адрес», и поведение бэкенда на необрезанном вводе не установлено; тяжесть последствия не установлена.

```gherkin
Дано пользователь на экране почты ввёл <адрес>
Когда он нажимает «Получить код»
Тогда запрос кода несёт <адрес на проводе> байт в байт
И виден экран кода, где адрес показан посимвольно как <адрес на экране>
```

| адрес | адрес на проводе | адрес на экране |
|---|---|---|
| `иван@пример.рф` | `иван@пример.рф` | `иван@пример.рф` |
| `jörg.müller@example.test` | `jörg.müller@example.test` | `jörg.müller@example.test` |
| `  ivan@example.test  ` — с пробелами по краям | `ivan@example.test` — обрезан | `ivan@example.test` |

## 3. Ввод и проверка кода

### 3.1 Кнопка «Подтвердить» доступна только при шести цифрах

Tier: 3 (hz-01, hz-06) — локальная фильтрация ввода — удобство; при её отказе неполный код уходит на сервер и отклоняется как неподходящий с сообщением 3.4; тяжесть последствия не установлена.

```gherkin
Дано пользователь на экране кода
Когда он вводит в ячейки <ввод>
Тогда ячейки показывают <содержимое>
И кнопка «Подтвердить» <состояние>
И запрос проверки не отправляется
```

| ввод | содержимое | состояние |
|---|---|---|
| `12345` | `12345` и пустая шестая ячейка | недоступна |
| `12a456` | `12456` — буква не принимается | недоступна |
| `123456` | `123456` | доступна |
| `012345` | `012345` — ведущий ноль на месте | доступна |
| `1234567` | `123456` — седьмая цифра не принимается | доступна |
| `١٢٣٤٥٦` — арабско-индийские цифры | пусто — не принимаются | недоступна |
| `１２３４５６` — полноширинные цифры | пусто — не принимаются | недоступна |

### 3.5 Сервис недоступен при проверке кода — одно сообщение, введённый код сохранён

Tier: 3 (hz-02, hz-04, hz-05, hz-06, hz-07, hz-08) — тот же маппинг 503, что и в 2.5 (Tier 2); дополнительная деградация — потеря шести введённых цифр, которые пользователь вводит заново; тяжесть последствия не установлена.

```gherkin
Дано пользователь на экране кода ввёл код, который сервис отправил на его адрес
И сервис временно недоступен
Когда он нажимает «Подтвердить»
Тогда видно сообщение «Сервис временно недоступен, попробуйте позже» без подробностей
И введённый код остаётся в ячейках, отсчёт продолжается
И кнопка «Подтвердить» снова доступна
И сервису ушёл ровно один запрос проверки — приложение не повторяет его само
Когда сервис снова доступен и он нажимает «Подтвердить»
Тогда виден экран «вошёл»
```

## 4. Истечение кода и повторная отправка

### 4.4 Пока идёт проверка или повторная отправка, остальные действия экрана кода не создают запросов

Tier: 3 (hz-02, hz-03, hz-04, hz-06, hz-08) — нажатие «Отправить новый код» или «Изменить адрес» в секунды полёта проверки — редкая комбинация поверх 3.3 (Tier 2); не установлено «не редко».

```gherkin
Дано пользователь на экране кода ввёл код, который сервис отправил на его адрес
И сервис отвечает на <запрос в полёте> с задержкой
Когда он запускает <запрос в полёте> и, не дожидаясь ответа, нажимает Enter в ячейке, «Подтвердить», «Отправить новый код» и «Изменить адрес»
Тогда сервису ушёл ровно один запрос — <запрос в полёте>
И экран не меняется, пока ответ не пришёл
И после ответа виден <результат>
```

| запрос в полёте | результат |
|---|---|
| запрос проверки | экран «вошёл» |
| запрос нового кода | экран кода с новым отсчётом и одним новым идентификатором запроса кода |

### 4.5 Отсчёт дошёл до нуля, пока идёт проверка

Tier: 3 (hz-02, hz-04, hz-07, hz-08) — гонка «ответ проверки приходит после нуля отсчёта» требует нажатия за секунду до истечения и медленного ответа одновременно; не установлено «не редко».

```gherkin
Дано пользователь на экране кода, срок кода для его адреса — несколько секунд
И сервис отвечает на проверку с задержкой дольше остатка срока и отвечает <ответ>
Когда он за секунду до нуля вводит код, который сервис отправил на его адрес, и нажимает «Подтвердить»
Тогда сервису ушёл ровно один запрос проверки
И после ответа <итог>
```

| ответ | итог |
|---|---|
| код принят | виден экран «вошёл» |
| код отклонён | видно сообщение «Срок кода истёк — запросите новый», ячейки закрыты, доступна только повторная отправка |

### 4.6 Сервис недоступен при повторной отправке — прежний код продолжает действовать

Tier: 3 (hz-02, hz-08) — недоступность сервиса ровно в момент повторной отправки — редкое пересечение двух не-happy-path ветвей; деградация — повторный ввод трёх цифр или новый запрос кода; не установлено «не редко».

```gherkin
Дано пользователь на экране кода ввёл три цифры, и пауза между отправками для его адреса прошла
И сервис временно недоступен
Когда он нажимает «Отправить новый код»
Тогда видно сообщение «Сервис временно недоступен, попробуйте позже» без подробностей
И три цифры остаются в ячейках, отсчёт продолжается от прежнего срока
И кнопка «Отправить новый код» снова доступна
Когда он дописывает прежний код и нажимает «Подтвердить»
Тогда запрос проверки несёт прежний идентификатор запроса кода
И виден экран «вошёл»
```

### 4.7 Срок уже истёк или пауза равна нулю в ответе сервиса

Tier: 3 (hz-01, hz-07) — срок в прошлом или нулевая пауза в ответе сервиса возникают при расхождении часов или нарушении контракта; сценарий лишь показывает истечение и не возвращает вход; не установлено «не редко».

```gherkin
Дано пользователь на экране почты ввёл свой адрес и сервис отвечает <ответ>
Когда он нажимает «Получить код»
Тогда <итог>
И отрицательного времени и сообщения «через 0 с» на экране нет
```

| ответ | итог |
|---|---|
| срок кода уже в прошлом | виден экран кода с «0:00» и сообщением «Срок кода истёк — запросите новый», ячейки закрыты, запрос проверки не отправляется |
| пауза между отправками равна нулю | он остаётся на экране почты и кнопка «Получить код» доступна сразу |

## 5. Навигация и перезагрузка

### 5.1 «Изменить адрес» возвращает на экран почты с уже введённым адресом

Tier: 3 (hz-04) — без «Изменить адрес» пользователь с опечаткой перезагружает страницу и вводит адрес заново — деградация до перезагрузки; тяжесть последствия не установлена.

```gherkin
Дано пользователь на экране кода
Когда он нажимает «Изменить адрес»
Тогда виден экран почты, в поле — его адрес, кнопка «Получить код» доступна
И запросы сервису не отправляются
Когда он меняет адрес на другой и нажимает «Получить код»
Тогда виден экран кода с новым адресом
```

### 5.2 Перезагрузка страницы возвращает на пустой экран почты

Tier: 3 (hz-04, hz-08) — отсутствие сессии после перезагрузки утверждается в Security 1.1 (Tier 2); остаток — пустое поле адреса и отсутствие запросов при открытии — косметика; тяжесть последствия не установлена.

```gherkin
Дано пользователь находится <где>
Когда он перезагружает страницу
Тогда виден экран почты с пустым полем адреса
И запросы сервису при открытии не отправляются
```

| где |
|---|
| на экране кода с идущим отсчётом |
| на экране «вошёл» |

### 5.3 Кнопки браузера «Назад» и «Вперёд» не возвращают чужой и не теряют текущий запрос кода

Tier: 3 (hz-08) — в Telegram Mini App нет кнопок «Назад»/«Вперёд» браузера; в обычном браузере деградация — повторный запрос кода; не установлено «не редко».

```gherkin
Дано пользователь на экране кода
Когда он нажимает «Назад» в браузере
Тогда виден экран почты с его адресом, запросы сервису не отправляются
Когда он нажимает «Вперёд» в браузере
Тогда виден экран кода с тем же адресом, тем же идентификатором запроса кода и продолжающимся отсчётом
И новый запрос кода не отправляется
```

### 5.4 Адрес с разметкой показывается на экране кода как текст

Tier: 3 (hz-05) — адрес вводит сам пользователь и видит только он; React экранирует текст по умолчанию, деградация — искажённое отображение собственного адреса; тяжесть последствия не установлена.

```gherkin
Дано пользователь на экране почты
Когда он вводит адрес, содержащий разметку `<b>x</b>@example.test`, и нажимает «Получить код»
Тогда на экране кода адрес показан ровно как введён, как текст, без разметки
```

### 5.5 Частично введённый код теряется при перезагрузке без подтверждения

Tier: 3 (hz-08) — запрос кода и сессия живут только в памяти по решению истории; деградация — повторный ввод кода после перезагрузки; не установлено «не редко».

```gherkin
Дано пользователь на экране кода ввёл три цифры из шести
Когда он перезагружает страницу
Тогда виден пустой экран почты
И запрос проверки кода сервису не отправлялся
```
