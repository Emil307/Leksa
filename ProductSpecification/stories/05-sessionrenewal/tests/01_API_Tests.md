# SessionRenewal — API Tests

> **Implementation Order**: Tests are numbered for sequential TDD implementation.
> Сначала закрепляется граница запроса, затем успешная ротация и только после неё — состояния отказа и конкуренция.

---

## 1. Валидация запроса

### 1.1 Недопустимый запрос обновления отклоняется без изменения сессии

Tier: 2 (hz-01, hz-04, hz-05, hz-06)

```gherkin
Дано существует действующая сессия
Когда клиент отправляет обновление токенов с недопустимым вариантом запроса
Тогда ответ имеет ошибку валидации
И действующая сессия остаётся без изменений
```

Примеры недопустимых вариантов: отсутствие допустимого JSON-тела;
отсутствующее поле, `null`, пустая строка, непечатный или многобайтовый
символ, строка длиннее 512 байт.

### 1.3 ASCII-токен предельной длины проходит валидацию

Tier: 2 (hz-01, hz-06)

```gherkin
Дано в хранилище нет сессии для ASCII-токена длиной 512 байт
Когда клиент отправляет обновление с этим refresh-токеном
Тогда ответ имеет единую ошибку авторизации
И ответ не имеет ошибки валидации
И ни одна сессия не изменена
```

## 2. Успешная ротация

### 2.1 Действующая сессия получает новую пару токенов

Tier: 1 (hz-04)

```gherkin
Дано существует действующая сессия и её access-токен ещё не истёк
Когда клиент обновляет токены по refresh-токену этой сессии
Тогда ответ успешен
И ответ содержит прежний идентификатор сессии
И ответ содержит новые refresh-токен и access-токен
И ответ содержит только разрешённые поля сессии
И новая строка сессии не создаётся
```

### 2.2 Новая пара сохраняет владельца и получает точные сроки

Tier: 2 (hz-01, hz-07)

```gherkin
Дано существует действующая сессия с фиксированным временем ротации
Когда клиент обновляет токены по refresh-токену этой сессии
Тогда новый access-токен относится к прежним пользователю и сессии
И срок access-токена равен времени ротации плюс настроенный access TTL
И срок сессии равен времени ротации плюс настроенный refresh TTL
И оба срока вычислены в UTC с точностью до секунды
```

### 2.3 Ротация не затрагивает соседние сессии

Tier: 2 (hz-04)

```gherkin
Дано рядом существуют другая сессия этого пользователя и сессия другого пользователя
Когда клиент обновляет токены первой сессии
Тогда первая сессия получает новую пару и новый срок
И обе соседние сессии остаются без изменений
```

## 3. Отказы и границы состояния

### 3.1 Недействительные refresh-токены неразличимы снаружи

Tier: 2 (hz-04, hz-05)

```gherkin
Дано подготовлены истёкший, неизвестный и уже использованный refresh-токены
Когда клиент по очереди запрашивает обновление с каждым токеном
Тогда каждый ответ имеет одну и ту же ошибку авторизации
И статус, код, сообщение и payload всех ответов побайтно совпадают
И ни одна сессия не изменена
И ни один запрос не выпускает действующую пару
```

### 3.2 Срок сессии имеет строгую границу истечения

Tier: 2 (hz-04, hz-07)

```gherkin
Дано время управляется относительно срока действующей сессии
Когда клиент обновляет токены непосредственно до срока, ровно в срок и сразу после срока
Тогда запрос до срока успешен
И запросы в срок и после срока имеют единую ошибку авторизации
И отклонённые запросы не меняют токен и срок сессии
И отклонённые запросы не выпускают действующую пару
```

### 3.3 Один refresh-токен выигрывает только одну конкурентную ротацию

Tier: 2 (hz-02, hz-03)

```gherkin
Дано два независимых запроса остановлены на одной точке ротации действующей сессии
Когда оба запроса продолжают обновление с одним refresh-токеном
Тогда ровно один ответ успешен
И второй ответ имеет единую ошибку авторизации
И в сессии зафиксирована ровно одна полная ротация
И новая пара победившего запроса остаётся действительной
```

## DSL Technical Reference

| DSL Statement | Technical Implementation |
|---------------|-------------------------|
| `клиент отправляет обновление токенов` | `POST /api/v1/auth/token/refresh` |
| `ответ имеет ошибку валидации` | HTTP `400`, `{code: VALIDATION_FAILED, message, payload}` |
| `единая ошибка авторизации` | HTTP `401`, `{code: UNAUTHORIZED, message, payload}` |
| `только разрешённые поля сессии` | Exact `session {id, refreshToken, accessToken}`; no `user`, `userId`, `expiresAt` |
| `фиксированное время ротации` | Injected UTC clock |
| `точностью до секунды` | Integer seconds and JWT NumericDate; test TTL `17` |
| `остановлены на одной точке ротации` | Deterministic barrier or conditional-storage interleaving |
| `полная ротация` | One atomic change of `refresh_token` and `expires_at` on the same row |
