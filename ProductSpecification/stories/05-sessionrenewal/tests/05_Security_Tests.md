# SessionRenewal — Security Tests

> **Implementation Order**: Tests are numbered for sequential TDD implementation.
> Сначала ограничивается входной DTO и область изменения, затем проверяются JWT и отсутствие раскрытия секретов.

---

## 1. Граница запроса

### 1.1 Недопустимый запрос ротации обрабатывается на границе запроса

Tier: 2 (hz-01, hz-05, hz-06, sec:MassAssignment, sec:InputLength, sec:InputValidation)

```gherkin
Дано существует действующая сессия
Когда клиент отправляет один недопустимый вариант запроса ротации
Тогда ответ имеет ошибку валидации
И ни одно поле сессии не изменено
И хранилище не получает значение токена
И ни одна сессия не изменена
И исходное значение токена отсутствует в перехваченных журналах
И дополнительная запись или поле с поддельным маркером не появляется
```

Примеры недопустимых вариантов: одно запрещённое серверное поле (`id`,
`user`, `userId`, `status`, `expires_at` или `accessToken`); слишком длинный,
многобайтовый или непечатный refresh-токен; refresh-токен с переводом строки
и маркером поддельной записи.

### 1.3 SQL-метасимволы обрабатываются как обычный неизвестный токен

Tier: 2 (hz-07, sec:SQLi)

```gherkin
Дано существуют сессии нескольких пользователей
Когда клиент отправляет неизвестный refresh-токен с SQL-метасимволами
Тогда ответ имеет единую ошибку авторизации
И ни одна сессия не изменена
И значение токена не появляется в журнале
```

## 2. Изоляция полномочий

### 2.1 Refresh-токен изменяет только принадлежащую ему сессию

Tier: 2 (hz-04, hz-05, sec:IDOR)

```gherkin
Дано пользователи А и Б имеют независимые действующие сессии
Когда клиент обновляет сессию refresh-токеном пользователя А
Тогда изменяется только названная токеном сессия пользователя А
И сессия пользователя Б остаётся без изменений
И ответ не принимает идентификатор владельца от клиента
```

### 2.2 Недоступная и отсутствующая сессии неразличимы снаружи

Tier: 2 (hz-05, sec:IDOR)

```gherkin
Дано подготовлены недоступный клиенту и отсутствующий refresh-токены
Когда клиент запрашивает обновление с каждым токеном
Тогда ответы имеют одинаковые статус, код, сообщение и payload
И ответы не раскрывают владельца или существование сессии
И ни одна сессия не изменена
```

## 3. Выпуск и раскрытие токенов

### 3.1 Новый access-токен имеет только разрешённый алгоритм и claims

Tier: 2 (sec:JWT)

```gherkin
Дано существует действующая сессия с фиксированным временем
Когда клиент обновляет токены этой сессии
Тогда новый access-токен подписан разрешённым алгоритмом
И подпись проверяется настроенным секретом
И токен содержит прежние идентификаторы пользователя и сессии
И токен содержит точный срок действия и не содержит лишних claims
```

### 3.2 Ответы и журналы не раскрывают токены и внутренние детали

Tier: 2 (hz-07, sec:JWT)

```gherkin
Дано известный секретный маркер проходит через каждое семейство отказа ротации
Когда клиент получает ответы для ошибок валидации, авторизации, подписи и хранилища
Тогда каждый ответ точно соответствует разрешённой схеме ошибки
И секретный маркер отсутствует в теле, payload и перехваченных журналах
И журналы используют фиксированный маркер редактирования там, где поле обязательно
И ответы и журналы не содержат SQL, stack trace, внутренние классы или пути
```

## DSL Technical Reference

| DSL Statement | Technical Implementation |
|---------------|-------------------------|
| `запрещённое серверное поле` | Any property outside `SessionRefreshRequest.refreshToken`; `additionalProperties: false` |
| `ошибка валидации` | HTTP `400`, `{code: VALIDATION_FAILED, message, payload}` |
| `единая ошибка авторизации` | HTTP `401`, exact `{code: UNAUTHORIZED, message, payload}` |
| `SQL-метасимволы` | Sentinel such as `' OR 1=1 --`; parameter-bound SQL |
| `маркер поддельной записи` | CRLF sentinel captured as data; no forged structured-log event or fields |
| `разрешённый алгоритм` | JWT `alg=HS256`; reject algorithm substitution during verification |
| `разрешённые claims` | Exact `sub`, `sid`, `exp` contract inherited from `EmailCodeLogin` |
| `семейство отказа` | Validation, unauthorized, signer failure, DB/commit failure |
| `фиксированный маркер редактирования` | Structured-log field contains a constant redaction value, never token text |
