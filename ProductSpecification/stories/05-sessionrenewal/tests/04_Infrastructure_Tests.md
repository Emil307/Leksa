# SessionRenewal — Infrastructure Tests

> **Implementation Order**: Tests are numbered for sequential TDD implementation.
> Сначала закрепляется откат инфраструктурных отказов, затем конфигурация и освобождение ресурсов.

---

## 1. Отказы зависимостей

### 1.1 Отказ хранилища откатывает ротацию целиком

Tier: 2 (hz-02, hz-04, hz-05)

```gherkin
Дано существует действующая сессия
И хранилище недоступно либо фиксация ротации завершается ошибкой
Когда клиент обновляет токены по refresh-токену этой сессии
Тогда ответ сообщает о временной недоступности
И прежние refresh-токен и срок сессии сохранены вместе
И старый refresh-токен остаётся действительным для следующей попытки
И частично действующая новая пара отсутствует
```

### 1.2 Ошибка выпуска токена не начинает ротацию

Tier: 2 (hz-04, hz-05)

```gherkin
Дано существует действующая сессия
И выпуск новой пары завершится ошибкой
Когда клиент обновляет токены по refresh-токену этой сессии
Тогда операция завершается контролируемой серверной ошибкой
И прежние refresh-токен и срок сессии не изменены
И хранилище не фиксирует ротацию
```

### 1.3 Отказы ротации имеют безопасные операционные сигналы

Tier: 2 (hz-07)

```gherkin
Дано по очереди подготовлены ошибка выпуска токена, ошибка хранилища и успешная ротация
Когда каждый вариант выполняется с идентификатором операции
Тогда каждый отказ создаёт собственный операционный сигнал с идентификатором операции
И сигналы отказов не содержат refresh-токен или внутренние детали
И успешная ротация не создаёт сигнал отказа
```

## 2. Конфигурация и ресурсы

### 2.1 Некорректная конфигурация токенов запрещает запуск приложения

Tier: 2 (hz-01, hz-05, hz-07)

```gherkin
Дано один из обязательных параметров токенов отсутствует, пуст или имеет недопустимое значение
Когда приложение запускается
Тогда запуск завершается явной ошибкой конфигурации
И приложение не подставляет значение для разработки
И ошибка не откладывается до первого запроса обновления
```

Проверяются access TTL, refresh TTL и JWT-секрет; для TTL также проверяются ноль,
отрицательное и нецелое значения. Для фиксированного момента проверяются точный
максимальный TTL, достигающий последней допустимой UTC-секунды, и значение на
одну секунду больше: первое принимается, второе запрещает запуск.

### 2.2 Соединение хранилища освобождается на каждом исходе

Tier: 2 (hz-06)

```gherkin
Дано зафиксировано исходное число занятых соединений хранилища
Когда успешное и ошибочное обновление токенов многократно повторяются
Тогда после каждого вызова число занятых соединений возвращается к исходному
И число занятых соединений не растёт от повтора к повтору
```

### 2.3 Дробная доля времени не меняет единицы TTL

Tier: 2 (hz-01)

```gherkin
Дано время ротации зафиксировано на половине секунды и TTL равен 17 секундам
Когда клиент успешно обновляет токены
Тогда срок сессии равен целой секунде времени ротации плюс 17
И срок access-токена равен той же целой секунде плюс 17, оба срока отбрасывают долю секунды одинаково
И ни один срок не умножен и не разделён на тысячу
```

## DSL Technical Reference

| DSL Statement | Technical Implementation |
|---------------|-------------------------|
| `хранилище недоступно` | PostgreSQL operation failure before commit |
| `фиксация ротации завершается ошибкой` | `UnitOfWork.commit()` failure with rollback |
| `временная недоступность` | HTTP `503`, `{code: UNAVAILABLE, message, payload}` |
| `выпуск новой пары завершится ошибкой` | JWT signer or refresh-token generator failure before transaction |
| `операционный сигнал` | Distinct structured event for signer failure versus DB/commit failure, with correlation id |
| `обязательные параметры токенов` | `ACCESS_TOKEN_TTL_SECONDS`, `REFRESH_TOKEN_TTL_SECONDS`, JWT secret |
| `точный максимальный TTL` | `floor((datetime.max UTC - fixed now).total_seconds())`; max+1 is rejected |
| `исходное число занятых соединений` | SQLAlchemy pool checked-out connection baseline |
| `целая секунда времени ротации плюс 17` | `exp = floor(now.timestamp()) + 17`; DB expiry is exact `floor(now) + 17s` (`SessionPolicy.truncate`) |
