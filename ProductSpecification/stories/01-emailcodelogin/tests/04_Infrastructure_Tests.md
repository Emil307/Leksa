# EmailCodeLogin — инфраструктурные тесты

> **Implementation Order**: Tests are numbered for sequential TDD implementation.
> Start с объявленной конфигурации запущенных сервисов, затем гарантии старта
> приложения и границ модулей и, последним, каскадное удаление в схеме авторизации.

Хранилище challenge — Redis, очередь писем и данные авторизации — PostgreSQL. Оба
поднимаются `infrastructure/scripts/run-infra.sh`; порты приходят из
`infrastructure/.env`, а не задаются в тесте.

**Граница истории.** Два блока вынесены в отдельные истории и здесь не проверяются:

- **Планировщик очереди, отправка писем и чистка** — `start` заканчивается вставкой
  строки. Про очередь здесь утверждается только то, что нужно для этой вставки.
- **Поведение при отказе хранилищ** — недоступный, зависший и перезапущенный Redis,
  отказ базы данных, давление памяти, откат при отказе очереди. Эта история считает
  Redis и PostgreSQL доступными; их отказы — предмет отдельной истории.

Номера сохраняют исходную нумерацию: секции 1 и 3 ушли целиком, и их номера не
переиспользуются.

## 4. Старт приложения и границы модулей

### 4.1 Приложение не стартует с негодной конфигурацией и называет переменную

Tier: 2 (hz-05, hz-07)

```gherkin
Дано переменная <переменная> имеет вид <вид>
Когда приложение запускается
Тогда запуск прерывается
И сообщение называет недостающую или негодную переменную
И рабочего значения по умолчанию в поставке нет
```

| переменная | вид |
|---|---|
| секрет подписи access-токена | отсутствует или пуста |
| подключение к хранилищу challenge | отсутствует или пусто |
| пространство имён шаблона письма | отсутствует или пусто |
| лимит попыток | ноль или отрицательное |
| время жизни кода | отрицательное или нечисловое |
| кулдаун повторной отправки | отрицательное или нечисловое |

## DSL Technical Reference

| DSL Statement | Technical Implementation |
|---------------|-------------------------|
| `хранилище challenge` | Redis (`REDIS_PORT` из `infrastructure/.env`) |
| `действующая конфигурация хранилища` | `CONFIG GET appendonly` = `yes`, `CONFIG GET appendfsync` = `everysec`, `CONFIG GET maxmemory-policy` = `noeviction` |
| `база данных` | PostgreSQL (`POSTGRES_PORT` из `infrastructure/.env`) |
| `таблица очереди` | `notifications.t_outbox` (`id`, `type`, `status`, `data`, `attempts`, `last_error`, `created_at`, `updated_at`) |
| `моменты создания и обновления заявки` | `notifications.t_outbox.created_at` / `updated_at`, тип `timestamptz` |
| `ожидающее состояние` | `notifications.t_outbox.status = ACTIVE` |
| `секрет подписи access-токена` | переменная конфигурации секрета JWT |
| `пространство имён шаблона письма` | `MAIL_TEMPLATE_NAMESPACE`, путь `email/{namespace}/email-code` |
| `проверяются фактические импорты` | `lint-imports` по контрактам слоёв `.importlinter` |
| `порт «положить заявку в очередь»` | единственный порт уведомлений, видимый модулю авторизации |
| `учётная запись провайдера` | строка `auth.t_auth`; `ON DELETE CASCADE` от `auth.t_users` |
| `строка сессии` | строка `auth.t_sessions`; `ON DELETE CASCADE` от `auth.t_users` |
