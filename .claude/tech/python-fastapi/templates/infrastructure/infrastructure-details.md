# Infrastructure Details — python-fastapi

Detailed reference for local development infrastructure.
For rules and quick reference, see `.claude/rules/infrastructure.md`.

## Local Development

All services run locally. Port isolation supports multiple repo instances in parallel — every port is
derived from `REPO_INDEX` in `infrastructure/.env` and read from there, never hardcoded.

### Port Configuration

Generated by `infrastructure/scripts/setup-ports.sh`:
- Backend (uvicorn): `8000 + REPO_INDEX`
- Frontend: `5173 + REPO_INDEX`
- Database (PostgreSQL): `5432 + REPO_INDEX`
- MailHog SMTP: `1025 + REPO_INDEX`
- MailHog HTTP: `8025 + REPO_INDEX`

### Service Scripts

| Script | Purpose |
|--------|---------|
| `run-backend.sh` | Start uvicorn (`uvicorn application.main:app --port $BACKEND_PORT`) |
| `run-frontend.sh` | Start the frontend dev server |
| `run-infra.sh` | Start Docker infrastructure (PostgreSQL, MailHog) |
| `migrate.sh` | Apply Alembic migrations (`alembic upgrade head`) |
| `stop-backend.sh` | Stop the backend by port PID |
| `stop-infra.sh` | Stop Docker infrastructure |
| `test-acceptance.sh` | Run acceptance tests with the correct env vars |

### Startup Order

1. `run-infra.sh` — DB must accept connections before migrations run.
2. `migrate.sh` — `alembic upgrade head`; the app does not migrate on boot.
3. `run-backend.sh` — the `lifespan` handler opens the async engine and closes it on shutdown.

### Network Flow (Local)

```
Browser -> frontend dev server (FRONTEND_PORT)
       -> /api/ -> uvicorn (BACKEND_PORT)

Backend:
  -> PostgreSQL (DB_PORT)         async engine, pool_pre_ping=True
  -> MailHog    (MAILHOG_SMTP_PORT)
```

### Health

- `source infrastructure/.env && curl http://localhost:$BACKEND_PORT/health`
- Readiness includes a DB round-trip; a 200 with the engine down means the check is not exercising the pool.

## Multi-Instance Notes

- Uvicorn runs with multiple workers in prod-copy and production — no process-local state (see `coding.md`, Deployment).
- Scheduled jobs take a distributed lock; see `templates/scheduling/implementation.md`.
